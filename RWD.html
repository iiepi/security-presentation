Introduction to Deadlock

In multiprogramming environments, multiple processes compete for a finite number of resources. Improper management of these resources can cause the system to freeze entirely.

  • Resources can be CPU cycles, memory space, files, or I/O devices.
  • Normal process lifecycle: Request a resource ⟶ Use it ⟶ Release it.
  • Conflicts happen when a process waits for a resource held by another.

What is a Deadlock?

A Deadlock is a specific state in an operating system where a set of processes are blocked because each process is holding a resource and waiting for another resource acquired by some other process.

Result: None of the processes can proceed. The system is at a complete standstill.

Necessary Conditions (Coffman)

For a deadlock to arise, the following four conditions must hold simultaneously in a system:

1. Mutual Exclusion

At least one resource must be held in a non-shareable mode. Only one process can use the resource at any given time.

2. Hold and Wait

A process is currently holding at least one resource and requesting additional resources held by other processes.

3. No Preemption

Resources cannot be forcibly removed from a process; they must be released voluntarily after the process completes its task.

4. Circular Wait

A closed chain of processes exists, where each process holds at least one resource needed by the next process in the chain.

Resource Allocation Graph (RAG)

A directed graph used to mathematically and visually model resource allocation and identify deadlocks.

  • Vertices (V): Divided into Processes (Circles) and Resources (Squares).
  • Resources: Can have a single instance or multiple instances (dots inside).
  • Edges (E):
    • Request Edge: Directed from Process to Resource (P → R).
    • Assignment Edge: Directed from Resource to Process (R → P).

Example of Deadlock using RAG

Golden Rule: If a graph contains a cycle and all resources only have a single instance, then a deadlock definitively exists.

Cycle: P1 → R1 → P2 → R2 → P1

In this example, P1 is waiting for R1 (held by P2). Simultaneously, P2 is waiting for R2 (held by P1).

This forms a closed loop leading directly to a Deadlock.

Deadlock Detection Concept

If a system does not employ deadlock prevention or avoidance algorithms, deadlocks can occur. Therefore, the OS must provide:

  • An algorithm that examines the state of the system to determine whether a deadlock has occurred.
  • An algorithm to recover from the deadlock.

When to run the detection algorithm?

Running the algorithm frequently consumes high CPU overhead. OS designers must balance the frequency of deadlocks against the computing cost of running the detection algorithms.

Detection: Single Instance Resources

If all resources have only a single instance, we can simplify the RAG into a structure called a Wait-For Graph.

  • We remove the resource nodes and collapse the edges.
  • An edge from P1 to P2 implies P1 is waiting for P2 to release a resource.
  • The system periodically invokes a cycle-detection algorithm (like Depth-First Search).

A deadlock exists IF AND ONLY IF the wait-for graph contains a cycle.

Detection: Multiple Instances

For systems with multiple instances of each resource type, a matrix-based approach is used (similar to the Banker's algorithm).

Available Vector

Indicates the number of available instances of each resource type.

Allocation Matrix

Defines the number of resources of each type currently allocated to each process.

Request Matrix

Indicates the current pending requests of each process.

Algorithm Logic

It simulates execution. If a process's request can be met by 'Available', it finishes and releases resources. If processes are left over, the system is deadlocked.

Banker's Algorithm

While primarily used for Deadlock Avoidance, understanding it is crucial for grasping safe states.

  • Safe State: The system can allocate resources to each process in some order and still avoid deadlock.
  • Concept: Just like a bank, the OS never allocates its available resources in a way that it can no longer satisfy the maximum needs of all its active customers (processes).

Deadlock Recovery Overview

Once a detection algorithm identifies a deadlock, the system must recover and restore normal operations. There are two primary approaches:

Process Termination

Aborting one or more processes involved in the circular wait to break the deadlock loop.

Resource Preemption

Preempting (taking away) resources from one or more deadlocked processes and giving them to others.

Recovery Methods Executed

1. Process Termination Strategies:

  • Abort all deadlocked processes: Breaks the deadlock instantly but comes with a high cost and data loss.
  • Abort one process at a time: Abort a process, rerun the detection algorithm, and repeat until the cycle breaks.

2. Resource Preemption Strategies:

  • Victim Selection: Which resources and which processes are to be preempted to minimize cost?
  • Rollback: Return the preempted process to a safe state and restart it from that state later.
  • Starvation: Ensure that the exact same process isn't continually picked as the victim.

Advantages & Disadvantages

Advantages

  • Allows maximum resource utilization compared to Prevention methods.
  • No strict, upfront constraints applied to how processes must request resources.

Disadvantages

  • CPU overhead to continuously run the complex detection algorithms.
  • Recovery can cause severe data loss if a process is aborted mid-write.
  • Requires complex rollback and state-saving mechanisms.

Conclusion

Deadlocks represent a fundamental challenge in concurrent programming and OS design. While prevention and avoidance algorithms are safer, Detection and Recovery provide a practical, high-performance alternative for environments where deadlocks are rare but manageable.

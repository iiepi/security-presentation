03 // RULESLOGIC

The Golden Rules

To be cryptographically secure, the function must satisfy:

  • Deterministic: Same input = Same output. Always.
  • Quick Computation: Must calculate efficiently.
  • Pre-Image Resistance: Impossible to reverse (One-Way).
  • Avalanche Effect: Small change in input = Huge change in output.
04 // SECURITYONE-WAY

The One-Way Function

Imagine a meat grinder. You can put a steak in and get ground beef.

Steak ➔ Grinder ➔ Ground Beef

But you cannot put ground beef back in and turn it into a steak.

This is why hackers who steal hashed passwords cannot simply "read" them. They only see the result, not the original password.

07 // AUTHENTICATIONSALT

Salting Passwords

To defeat pre-computed "Rainbow Tables", we add random noise.

let salt = randomBytes(16); // "x9#kL2..."
let dbEntry = Hash(password + salt);

Now, even if two users have the password "123456", their hashes will be completely different because their salts are different.

08 // INTEGRITYCHECK

Integrity Checks

How to ensure a downloaded file is not corrupted or hacked?

  1. Developer releases Software.zip + Hash.
  2. You download the zip file.
  3. You run a hash tool on your local copy.
  4. Compare your hash with the developer's hash.

Match = Safe. | Mismatch = TAMPERED.
